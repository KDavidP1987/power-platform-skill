Iteration 1, on an earlier draft of the skill with a simpler first test, scored 96% with the skill and 52% without. Test 1 was then rewritten to have three plausible causes instead of one, which is where the gap widened most.

Does it load when it should?

A skill that never loads helps no one, and one that loads for the wrong work wastes tokens. Twenty requests were written: ten that need the skill and ten near misses that share its vocabulary but not its job, such as a Power BI DAX measure, a Dynamics 365 C# plug-in, a Power Automate Desktop flow, a Logic Apps workflow in Bicep and a React client for the Dataverse Web API.

Held-out requests
8 of 8 correct
Training requests
11 of 12 correct (was 10)
False triggers
0 in every round

Each request ran three times per round over five rounds of description tuning. Twelve requests tuned the description; eight were held back to judge it. The shipped description tied the original on the held-back requests and loaded more reliably on the training ones.

How it was measured, and its limits

  • Same model, same prompt, two runs. Each task ran once with the skill available and once with no skill, in separate agents with no shared context.
  • Machine checks where possible. The flow definitions went through the bundled flow linter, the .pa.yaml files through the bundled compile-fault checker, and the scripts through node --check. A grader model judged the rest against the written checks and had to quote its evidence.
  • One run per configuration. There is no variance estimate. Treat the gap, not the exact percentages, as the finding.
  • Nothing ran against a live tenant. The checks judge the answers' correctness on paper. The skill's own rule is that only performing the task in the published app proves a change, and this evaluation could not do that.
  • Three checks were too lenient. The graders flagged them: test 1's "checks before fixing" passed a baseline that checked the wrong causes; test 3's Dataverse check passed an optional query that is off by default; test 4 lumps two delegation facts into one check. Tightening them would widen the gap, not narrow it.
  • Measured before the last additions. Thirteen smaller references were added after iteration 2. None of the four tests exercises them.
